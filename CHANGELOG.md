# Changelog

## 2026-06-03

- **⚠️ Config-driven power sensors (breaking env change), replacing the `Cumulus` & `Lave-linge` slices** — the two were byte-identical power→energy slices (a Zigbee2MQTT/ESPHome device reporting only instantaneous power, integrated into daily kWh, shown as one bottom-table row) differing only in their env var, table and label. They're collapsed into **one generic slice driven by a single variable**: `POWER_SENSORS`, a `;`-separated list of `topic:Display Name` entries (the first `:` splits topic from label). Adding a new power sensor is now **a config line, no code**. Each entry gets its own MQTT listener + integrator, stores into a shared `daily_power(slug, …)` table (slug = slugified label) and renders one row (yesterday / daily-average / trend), in config order, above the always-shown `Talon` row. A one-time, idempotent DB migration copies the old `daily_cumulus` / `daily_washer` rows into `daily_power` under slugs `cumulus` / `lave-linge`, so **trend history is preserved as long as the labels stay `Cumulus` and `Lave-linge`**. The `Alertes` board's `Cumulus` domain (rise/drop rules) now reads the sensor labelled `Cumulus`; behaviour and layout are unchanged (the rendered golden is byte-identical). **On CasaOS: remove `CUMULUS_TOPIC` and `WASHER_TOPIC`, add `POWER_SENSORS="zigbee2mqtt/cumulus:Cumulus;zigbee2mqtt/washing_machine:Lave-linge"`** (keep those two labels to inherit the history). The shared `MQTT_*` broker config and the `Eau` (Water) slice are unchanged.
- **`Lave-linge` (washing machine) consumption + layout rework** — a new optional slice mirrors `Cumulus`: a Zigbee2MQTT smart plug reports only instantaneous power, integrated into daily kWh (no backfill), shown as a `Lave-linge` row in the bottom table (between `Cumulus` and `Talon`) with yesterday / daily-average / trend. Enable it with `WASHER_TOPIC` (plus the shared `MQTT_HOST`, see below). The dashboard layout is reworked at the same time: the **`EDF` consumption chart now fills the whole left column** (with the bottom table beneath it), and the **`Solaire` (Solar) chart moves under the `Eau` (Water) chart** in the center column, which splits at mid-height (`Eau` top, `Solaire` bottom). Goldens regenerated.
- **⚠️ Shared local MQTT broker config (breaking env change)** — the `Cumulus`, `Lave-linge` and `Eau` (Water) slices all talk to the **same local broker**, so the host/port/credentials are now configured **once** via `MQTT_HOST` / `MQTT_PORT` / `MQTT_USERNAME` / `MQTT_PASSWORD`; each slice keeps only its own `*_TOPIC`. A slice is enabled when `MQTT_HOST` **and** its topic are set (an empty `MQTT_HOST` disables all three). **On CasaOS: remove `CUMULUS_MQTT_HOST/PORT/USERNAME/PASSWORD` and `WATER_MQTT_HOST/PORT/USERNAME/PASSWORD`, add the new `MQTT_*` block, and set `CUMULUS_TOPIC` / `WATER_TOPIC` / `WASHER_TOPIC`** (the topics no longer have a default). EcoFlow's cloud broker is separate and unaffected.
- **`Talon` (baseline power): computed over a solar-free night window** — the talon (the home's permanent standby draw) is now the **P20 of the Linky load curve restricted to 23h–05h**, instead of the P5 over the full 24h. The Conso curve is grid draw (soutirage), already net of self-consumed solar, so an EcoFlow PowerStream's daytime injection used to crush the curve toward 0 and drag the talon **below** the home's real baseline; the night window is solar-free, so the reading is honest again. The percentile rises 5→20 to keep skipping the deepest dips over the ~12 night samples. A one-time `user_version` DB migration NULLs the old 24h talons so they re-fetch and recompute night-only on the next refresh — no action needed, no new environment variable. The panel layout is unchanged.
- **`Réseau` (Network): data-usage trend over the last 30 days** — the `Données hier/30j` (Data yesterday/30d) line now carries a ▲▼ trend comparing the **last 30 days to the prior 30** — whether the home used more or less data overall lately (neutral black arrow; more/less data isn't inherently good or bad). Computed straight from the daily WAN report (no DB, no backfill); the report fetch window grows 35→65 days to cover both windows, so the trend appears once ~60 days of history exist. Replaces the previous 7-day daily trend on that line. No new environment variable.
- **`Home` next-refresh time matches the device's real next wake** — when clock drift wakes the ESP a minute before a boundary (e.g. 09:59 for the 10:00 wake), the firmware skips that boundary and sleeps to the next one (12:00); the `Home` panel used to show the raw next boundary (`09:59 ► 10:00`) and now shows the device's real next wake (`09:59 ► 12:00`). New optional env var `SCREEN_WAKE_SKIP_MIN` (default 5) — keep it equal to the firmware's `sleep_min < 5` guard.
- **ESP32 firmware: boot diagnostics** — each boot logs its reset reason and wake cause over serial (timer wake vs a full power loss vs brownout), to tell a healthy 2 h timer wake apart from a power-supply issue (e.g. a host USB port cutting 5 V when it sleeps). Reflash to apply.
- **Documentation now fully in English** — all docs (`README.md`, `CHANGELOG.md`, `CLAUDE.md`) read in English; each on-screen French string keeps its literal but gets an English gloss (e.g. `Réseau` (Network), `Eau` (Water)), while the code's French UI labels are untouched (the screen stays French).

## 2026-06-02

- **`Home`: displayed time = real moment of the pull** — the left time of the `Home` panel (`Écran  HH:MM ► HH:MM`) is no longer the **refresh boundary** frozen at data-build time (≈`DATA_LEAD_MIN` before the boundary), but the **real moment of the `GET /display`** — when the ESP pulls the image — recomputed on every pull (with the next even-hour boundary on the right). Rendering now happens **on every pull** (no longer only when crypto is enabled); on a render error it falls back to the cached buffer. No environment variable; `build_dashboard_data` unchanged → goldens unchanged.
- **ESP32 firmware: guaranteed deep sleep + bounded retry** — every path now ends in a **deep sleep**: a PSRAM allocation failure no longer hangs awake forever in an infinite loop (`while(1)`), it sleeps and retries like the other errors. Failed cycles (WiFi/PSRAM/fetch) go through a **back-off retry** — up to `MAX_QUICK_RETRIES` (3) quick wakes (5 min) for a brief outage, then falling back to the full interval (2 h) to preserve the battery; the counter lives in **RTC memory** (survives deep sleep) and resets to 0 after a clean cycle. The **NTP** sync result is now checked and logged; with no valid clock the sleep lasts one **full interval** (instead of a hard-coded 1 h) and a later wake with NTP up realigns itself onto the even hours. New firmware constant `MAX_QUICK_RETRIES` — **reflash the ESP32** to enable.
- **Tree restructuring: `hardware/` vs `server/`** — clean split of the physical and server sides, root reduced to `README.md` + `CHANGELOG.md` (+ `CLAUDE.md`). The **ESP32 firmware** (`hardware/esp32-display/`), the **3D case** (`hardware/case/Dashboard.3mf`) and the **photo** (`hardware/device.jpg`) move under `hardware/`. The whole server moves under `server/`: the **package** `server/app/`, the **golden net** `server/tests/`, the **Docker infra** `server/infra/` (`Dockerfile` + `docker-compose*.yml` + `.env.example`), the **scripts** `server/scripts/` (`gen_preview.py` + `preview.png`) and the `requirements*.txt`. `server/` becomes the **Python import root**: `python -m app` and `pytest` run **from `server/`** (`app/` and `tests/` stay top-level packages, no internal import changed). CI updated (Docker build `context: server` + `file: server/infra/Dockerfile`; tests with `working-directory: server`). **Deployment**: no environment variable added or renamed — the CasaOS runtime (pre-built image) is unaffected; however the compose import URLs change (`…/main/server/infra/docker-compose.yml` and `…casaos.yml`), and the local `.env` now lives at `server/infra/.env`. Pure move (git history preserved), no rendering change — goldens unchanged.
- **Screen refresh every 2 h + server update aligned to it** — the ESP32 firmware no longer wakes at two fixed hours (8 h/17 h) but on a **clock-aligned interval** (`REFRESH_INTERVAL_MIN = 120` → 00:00, 02:00 … 22:00). On the server side, the loop no longer runs on a blind hourly cycle: it regenerates the buffer **`DATA_LEAD_MIN` minutes (10) before** each screen wake, so the ESP always pulls a render at most a few minutes old (`app/schedule.py`, the shared single source of truth). The `Home` panel drops its two lines for a **single line** — `Écran  14:00 ► 16:00` — showing the current screen-refresh time and the next, both derived from the same schedule. **Environment variables**: `REFRESH_INTERVAL` is replaced by `SCREEN_REFRESH_INTERVAL_MIN` (120, must match the firmware) and `DATA_LEAD_MIN` (10) — to update on the CasaOS deployment. Goldens regenerated.
- **Golden-master anti-regression net (`tests/`)** — before the architectural refactor, a **pytest** suite freezes a known input (seeded SQLite DB + frozen clock) and compares the output bit-for-bit against committed references: **data layer** (`build_dashboard_data()` → `tests/fixtures/data.golden.json`, portable, covers the orchestrator + the DB-backed slices + the alerts) and **render layer** (`render_dashboard()` → `png_to_epd_buffer()` → `tests/fixtures/display.golden.bin`, the 163,200-byte EPD buffer; actual/golden/diff PNGs in `/tmp` on a mismatch). Run `pytest -q` (must stay green), re-baseline with `--update-golden`. CI **GitHub Actions** (`.github/workflows/tests.yml`) on push + PR. `Pillow` is now **pinned** (rendering is sensitive to FreeType, which differs by about 5% of the buffer macOS↔Linux): the data layer is byte-exact everywhere (strict guard), the render layer is strict locally and a simple smoke test in CI (`GOLDEN_TOLERANCE`). No deployment environment variable added.
- **`Alertes` (Alerts) panel (top-left gutter)** — under the `Home` panel, a **per-domain status board** (`EDF`, `Eau` — Water, `Solaire` — Solar, `Réseau` — Network, `Cumulus`, `Crypto`) built from the already-computed daily trends. Each monitored domain is a **section title** with its separator, followed by **plain-language messages** (rendered in French on screen; English in parentheses): a problem in **red** (« Forte hausse de consommation 15%/j » — sharp rise in consumption, « Fuite d'eau probable 240 L » — probable water leak, « Panneaux solaires déconnectés ? » — solar panels disconnected?, « Latence réseau élevée » — high network latency…) or a **positive** note in **black** (« Forte production solaire » — strong solar production, « Belle baisse de consommation » — nice drop in consumption, « Bot devant le hold » — bot ahead of buy-and-hold…). Each line adds, when computable, its **financial impact** — `dépense`/`économie` (spend/save) in €/day (EDF consumption, off-peak hours, standby, cumulus, water), € (solar production) or `gain`/`manque` (gain/shortfall) in $ for **Crypto** (the strategy's gain estimated via the **alpha** × the invested amount). A healthy domain shows « Rien à signaler » (nothing to report). Hard-coded thresholds (tunable in `app/alerts.py`), no new environment variable (reuses `PRICE_HP`/`PRICE_HC`).
- **`Home` panel (top-left gutter)** — a `Home` section title showing the **day + time of the last update** and the **time of the next**, in the free space to the left of the packed columns.
- **Zero bars = line** — in the `Solaire` (Solar) and `Eau` (Water) charts, a **zero** value now draws a **baseline** (like the `N/A` marker) instead of nothing, so a day at 0 stays visible.
- **`Réseau` (Network): rolling "month" + sections named by SSID** — the "data" total of the `Réseau` panel is no longer calendar-based (it dropped to ~0 on the 1st of the month) but **rolling over the 30 complete days ending yesterday** — always a full, day-to-day comparable window; the line is relabelled `hier/30j` (yesterday/30d). The two client mini-tables now carry the **real SSID name** (`UNIFI_SSID_MAIN`/`UNIFI_SSID_IOT`, e.g. `Atchoum` / `Iotchoum`) as a header, instead of the generic `Perso`/`IoT` (falls back to the generic if the variable is empty).
- **`Réseau` (Network): top-4 clients + "aujourd'hui" (today) marker** — the client mini-table of the `Réseau` panel goes from top-3 to **top-4** by traffic, and each network header carries a **« · aujourd'hui »** (today) marker (e.g. `Perso · aujourd'hui … 4 clients`) noting that the shown traffic is each client's current-session rx+tx. The main network (Perso) is rendered first; if screen height is short, the last line of the IoT network (smallest traffic) is trimmed by the existing degradation.
- **Columns packed to the right** — the `Solaire` (Solar)/`EDF` and `Eau` (Water) columns are shifted right to sit against (8 px gap) the right-anchored `Crypto`/`Réseau` (Network) column, so the empty space ends up at the far left of the screen instead of being stuck between the `Eau` and `Crypto` columns.

## 2026-06-01

- **Solar "today" bar fix (real root cause)** — today's solar bar was stuck at `0` even though production was accumulating correctly in the database. The read-back query used an **exclusive** upper bound set to *today*, so `WHERE date < today` dropped today's own row and fell back to 0. The bound is now *tomorrow*, matching the water slice. (The earlier keep-alive/echo and threshold changes were genuine improvements but not the cause of this symptom — the `today` bar had never worked since it was introduced.)

- **Solar "today" bar fix** — today's solar bar showed **N/A** despite live production. The MQTT listener subscribes to the same topic it publishes its 60s keep-alive request to, so the broker echoed that request back; sharing the heartbeat's `cmd_func/cmd_id` but carrying an empty payload, it decoded to a phantom **0 W** sample that claimed the whole interval since the last real reading at zero watts, collapsing the day's integral to ~0. Payload-less control echoes are now ignored (a genuine night-time 0 W heartbeat still carries a full payload, so it is unaffected), and the listener no longer subscribes to the `…/property/get` topic it publishes to, removing the echo at its source.
- **Solar chart shows every yield** — the solar chart no longer hides small days behind an `N/A` floor: any value, however small (down to 0), now draws a bar. The `N/A` threshold still applies to the EDF consumption chart only — useful for small PV setups whose daily yield can sit below the old 0.05 kWh floor.
- **Water meter consumption** — optional `Eau` (Water) chart in the top-center space, between the Solar chart and the Crypto panel: the last **9 days** of water use as daily-litres bars, with a title showing the average **L/day** (and trend), the month-to-date **m³** and its **€** cost. An ESPHome wM-Bus reader publishes the meter's cumulative index (m³) over MQTT; the dashboard derives daily litres by **index difference** (not power integration, unlike Cumulus) — no backfill, history starts at first connection. A day with no reading shows **N/A**, including today until its first frame arrives. Enabled by setting `WATER_MQTT_HOST`.
- **Solar & water "today" bar** — the Solar and Water charts now end on **today** (rightmost bar labelled `Auj.`) instead of yesterday, so the current day's accumulation is visible. The EDF consumption chart still ends on yesterday (no same-day data).
